# Ustam 1.0.0-beta.3

[English](release-ustam-v1.0.0-beta.3.md) · [Türkçe](release-ustam-v1.0.0-beta.3.tr.md)

This prerelease updates the shared local hub and all three provider distributions. The Mac arm64 package includes the verified current UI and pinned provider engines. The 55-second Turkish trailer is available from the README and release assets.

## Work protocol

- A bounded contract records scope, file ownership, acceptance criteria and approved commands before implementation.
- A separate acceptance-test-author role supplies good and bad examples. The local controller rejects weak packs and requires criterion coverage before production implementation.
- Preparation creates an isolated Git worktree while preserving staged, unstaged and non-ignored untracked context. Candidate freezing binds content, modes, index, HEAD, contract and test pack; concurrent ownership conflicts are refused.
- Scoped questions can serve related works with one answer. Contract changes invalidate stale answers and approvals. Material scope changes require human consent bound to the contract version.
- Verification and integration checks bind observed local commands and deterministic artifact checks to the frozen candidate and current project context. Helper-reported results remain unverified. Evidence-backed result cards become invalid when the candidate, tests or execution environment changes.
- Applying changes needs explicit Works approval. Versioned records, operation IDs, cancel/resume and retained candidates support recovery without automatically replaying interrupted operations.

This is a manual native bridge invoked by the provider's installed work-protocol tool. There is no automatic provider hook or paid controller call. Built-in checks support `contains` and `json_equals`; browser behavior, performance and semantic research quality are not supported acceptance-check kinds. Role names are reported provenance, not signed identity attestations. Worktrees are not security sandboxes.

## Safety and provider fixes

Ownership now rejects canonical path aliases and overlapping active writes. Apply/rollback checks file identity to preserve concurrent external edits, retaining recovery bytes when rollback cannot safely proceed. Claude restoration preserves the exact prior installation-manifest identity. OpenCode role/tool permissions and bundled provider instructions are aligned with the bounded workflow. Configured Codex model routing is honored. Engines are pinned by commit with exact file hashes; account/model availability remains conditional.

## Usage and interface

The project chooser combines ready, custom and saved teams with helper/model settings in the setup area. Codex usage indexing is bounded, chronologically normalized and cached with append snapshots and unchanged-file reuse. Cache edge cases and accounting dependencies are covered. The UI improves project selection, pending-state and locale handling, usage loading and Works handoff. Fourteen accessible SVG icons replace the interface's text-symbol icons and use the current text color. The Turkish trailer includes original music and sound effects, without spoken narration; its usage figures are sample data.

## Mac packaging and startup

Package integrity checks cover native binaries/frameworks and required UI modules. The source installer preserves identified existing apps through backup and keeps project settings/state. Owned build-process cleanup, interrupted-build reporting, reopening and startup/browser notices are improved. The Script Editor guided source installation route still awaits an actual user Run acceptance test.

## Downloads and limits

The new native asset is **macOS arm64**. Windows/Linux beta.2 downloads remain the previous version; no beta.3 Windows/Linux binaries are published here. GitHub source archives contain this release's current source.

The Mac bundle was built, installed and opened locally on one development Mac, with UI, lifecycle, packaging and preservation checks. This does not establish that a quarantined public download opens. Apple Developer ID signing/notarization are unavailable; Gatekeeper restrictions remain unresolved. Windows runtime and paid model calls were not tested for this release. The protocol is recoverable rather than a cross-filesystem transaction; interrupted apply can leave partial user-approved edits and requires inspection. No bug-free or universally trusted installation claim is made.
